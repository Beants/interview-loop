# 面试题 — 候选人A（实习生）

> 岗位：后端架构师 / AI 工程化专家（实习生）
> 面试时长：30-40分钟（实习生缩短）
> 日期：2026-06-05
>
> **使用范围**：前六部分保留历史实习生示例，不作为当前时长、题型或评价边界的配置源。实际出题统一读取 `../SKILL.md` §分层标尺（SoT）和 Step 5；E 类执行第七部分，不沿用历史“可选编码”安排。成长证据按原则五及使用者已确认的要求取证，不从空窗、待遇关注、休息需求或表达热情推断能力或诚信。

## 面试节奏设计

| 阶段 | 时长 | 内容 | 目的 |
|------|------|------|------|
| **开场** | 2min | 介绍团队方向，请候选人自我介绍 | 破冰，观察表达能力 |
| **项目深挖** | 12-15min | 选GNN+PPO项目深挖，兼顾仿真系统设计 | 验证技术深度、系统建模能力、真实理解 |
| **AI认知探索** | 8-10min | 从他的RL经验引申到LLM/Agent | 验证AI知识广度和迁移学习能力 |
| **编程/工程基础** | 5-8min | 代码习惯、工程化意识、工具链 | 验证能否快速融入工程团队 |
| **学习意愿** | 3-5min | 职业规划、自学情况、求职动机 | 验证培养价值 |
| **反问** | 3min | 候选人提问 | 观察关注点 |

## 第一部分：项目深挖（12-15min）

### 1.1 GNN+PPO路由优化项目（核心深挖）

> 从简历看这是他当前最新的项目，技术含量最高，重点深挖

**L1 做了什么：**

- Q1：这个项目的研究背景是什么？你解决的核心问题是什么？
- Q2：你在这个项目中具体负责哪些部分？哪些是你独立完成的？

**L2 怎么做的：**

- Q3：你把网络拓扑建模为图结构，具体的特征有哪些？节点特征是什么？边特征是什么？
- Q4：PPO的**状态空间、动作空间、奖励函数**分别怎么设计的？为什么这么设计？
- Q5：你提到了"工程化训练流水线"，具体包括哪些模块？为什么要做多随机种子和多算法对照？
- Q6：你做的离散事件仿真平台，Drone、Channel、Center这些组件是怎么抽象的？之间的关系是什么？

**L3 为什么这么做：**

- Q7：为什么选择GNN而不是MLP或CNN来处理网络拓扑？GNN在这里的核心优势是什么？
- Q8：为什么用PPO而不是DQN或A3C？PPO的clip机制你知道是什么吗？
- Q9：多进程并发架构中，每个节点独立运行四大协程，为什么不用线程？为什么用协程？
- Q10：TDMA和CSMA-CA两种MAC协议，你在实现中是怎么切换的？为什么要支持双协议？

**量化追问：**

- Q11：路由优化的效果如何？时延降低了多少？成功率提升了多少？有没有baseline对比？
- Q12：CUDA加速矩阵计算，具体加速了多少倍？有没有做过profiling？

### 1.2 IEEE 802.11e EDCA仿真系统（快速验证）

- Q13：SimPy的离散事件仿真机制，底层是怎么实现的？用的是Python的什么特性？
- Q14：马尔可夫链的转移矩阵是怎么构造的？稳态分布是怎么求的？迭代收敛的条件是什么？
- Q15：AIFS、退避冻结、TXOP这些概念，你能用通俗的话解释一下吗？

### 1.3 上位机软件项目（快速验证）

- Q16：这个项目是企业委托的？具体是什么企业？合同金额大概多少？
- Q17：WinForms + WPF混合架构，为什么要混合？遇到了什么兼容性问题？
- Q18：串口通信的实时刷新，为什么用InvokeRequired/Invoke？直接操作会怎样？

## 第二部分：AI认知探索（8-10min）

> 目的：从他的深度学习经验引申到LLM/Agent，测试知识迁移能力

### 2.1 从RL到LLM的迁移

- Q19：你做PPO强化学习，和ChatGPT训练中的RLHF有什么关系你知道吗？
  - **期望**：能说出RLHF用了PPO或类似算法来对齐人类偏好，说明有迁移学习能力
  - **如果不了解**：简单解释RLHF，然后问"你觉得和你做的PPO有什么异同？"

- Q20：你了解Transformer架构吗？注意力机制的核心思想是什么？
  - **期望**：至少知道self-attention和序列建模的基本概念
  - **GNN的注意力机制**：GAT中的注意力和Transformer的注意力有什么异同？

### 2.2 LLM/Agent认知

- Q21：你用过ChatGPT/Claude这类大模型吗？在你的研究或项目中怎么用的？
- Q22：你听说过RAG（检索增强生成）吗？能说说你的理解吗？
  - **如果了解**：追问"你觉得RAG和传统搜索引擎的区别是什么？"
  - **如果不了解**：简单解释，然后问"如果让你设计一个让大模型基于知识库回答问题的系统，你会怎么设计？"

- Q23：你听说过AI Agent（智能体）吗？你觉得它和你做的强化学习智能体有什么区别？
  - **期望**：能理解"在环境中做决策"这个共通点
  - **如果了解**：追问"你觉得Agent最核心的技术挑战是什么？"

- Q24：如果让你用大模型做一个应用，结合你现有的知识背景，你最想做什么？
  - **考察**：创新能力、将技术与场景结合的能力

### 2.3 Prompt工程基础

- Q25：你有没有写过Prompt（提示词）？你觉得写好Prompt的关键是什么？
  - **目的**：看是否有基本的结构化表达能力，不需要专业Prompt工程经验

## 第三部分：编程/工程基础（5-8min）

### 3.1 代码质量意识

- Q26：你的仿真系统代码量大概多少行？有没有做模块拆分？
- Q27：你写代码有写测试吗？用的什么测试框架？
- Q28：你用过Git吗？平时怎么管理代码的？有做过code review吗？

### 3.2 工程化意识

- Q29：你的训练流水线（checkpoint保存、CSV指标落盘），这个设计思路是怎么来的？是参考了什么框架还是自己想的？
- Q30：如果现在让你把仿真系统部署成一个Web服务，让其他人通过网络调用，你会怎么做？
  - **期望**：能说出Flask/FastAPI + HTTP接口的基本思路
  - **如果不了解Web开发**：问"你觉得需要哪些组件？"

### 3.3 快速编码测试（可选）

如果面试中需要验证编码能力，可以给一个简单题目：

```
用Python实现一个简单的LRU Cache，支持get和put操作，O(1)时间复杂度。
```

**期望**：能用字典+双向链表（或OrderedDict）实现，考察基本数据结构功底。

## 第五部分：C 类场景排查题（社招版，10-15min，实习生版不设）

> 用途：验证**诊断性深度**——生产故障场景下的假设树、排查顺序、信息澄清意识。这类能力只能靠真排过坑，背书背不出来（A 类验"知不知道"、B 类验"不会时怎么反应"、C 类验"系统静默劣化时第一步看哪"）。
> 出题方式：**口述场景，故意留信息缺口**，观察候选人问不问。判卷听过程不听终答。
> 题源纪律：优先用面试官自己修过的真 bug 脱敏出题（有 ground truth、外部背不到）；以下为通用成题，任何团队可直接用。

### C1 静默失败类（HTTP 200 + 空 payload）

| 栏目 | 内容 |
|------|------|
| **题面（口述）** | "第三方网关调用量正常、返回全是 200，但业务方说拿到的数据是空的，日志零报错。你从哪开始查？" **（故意不说：token 有效期/网关版本）** |
| **考察点** | 对静默失败的敏感度：200 ≠ 成功；会不会先验鉴权链路而不是先怀疑业务代码 |
| **好答案的形状** | 先问澄清（哪个接口/哪个时间段/哪个租户/报文原文长什么样）；第一反应"零报错本身就可疑，先抓一个真实报文看 payload"；假设树：鉴权链路（token 失效被网关静默降级成空集）→ 数据源侧过滤（权限/租户上下文为空）→ 版本兼容（网关新版本改了响应结构）；判别顺序从便宜到贵：抓报文 → 验 token（introspect）→ 比对新旧版本 |
| **危险信号** | 直奔"加重试""换模型"；假设树只有一根枝；全程不问澄清，直接断言根因 |

### C2 工具链路类（agent 说"功能暂不可用"）

| 栏目 | 内容 |
|------|------|
| **题面（口述）** | "agent 代码零改动，某天开始用户问订单相关问题时，它总回复'该功能暂不可用'。代码 review 无 diff。查哪？" **（故意不说：请求头/权限配置/工具注册机制）** |
| **考察点** | 会不会想到工具注册/过滤链路，而不是停在模型或提示词层 |
| **好答案的形状** | 先问：agent 是"知道有这工具但调失败了"还是"根本看不到这工具"？→ dump 可见工具列表 → 若工具缺失，查工具注册链路：权限上下文（请求头缺失→权限为空→工具被过滤）→ 工具服务健康 → 配置变更记录。关键直觉：**AI 说"不可用"不一定是它能力不行，可能是它拿不到工具** |
| **危险信号** | 卡在"改 prompt 试试"出不来；想不到"模型可见的工具列表"这一层；把现象当模型幻觉 |

### C3 RAG 分层劣化类（时好时坏）

| 栏目 | 内容 |
|------|------|
| **题面（口述）** | "RAG 上线三个月，某类问题准确率从 90% 掉到 60%，而且**时好时坏**。定位思路？" **（故意不说：文档更新节奏/索引版本/切分配置变更）** |
| **考察点** | 分层定位意识（解析→切分→索引→召回→重排）+ "时好时坏 = 存在离散变量"的推理 |
| **好答案的形状** | 先问澄清：哪类问题？哪批文档？什么时间点开始？→ 缩小到某一层再下钻；"间歇性"应联想到离散变量：新旧索引并存（部分请求打到旧索引）/ 文档增量更新时切分参数漂移 / 多副本配置不一致；给出分层排查清单而非单点猜测 |
| **危险信号** | 一口咬定单一原因（"embedding 模型变了"）不验证；不问"哪类问题、哪个时间点"；把"时好时坏"当噪声忽略 |

### C4 agent 环路类（反复调同一工具）

| 栏目 | 内容 |
|------|------|
| **题面（口述）** | "长任务跑到第 8 轮，agent 开始反复调用同一个工具，每轮返回结果都一样，停不下来。这是什么问题、怎么检测、怎么止住？" **（故意不说：上下文管理策略/记忆设计）** |
| **考察点** | 环路检测 + 目标重注入——考的是"知道 agent 环路的机理"而非背参数 |
| **好答案的形状** | 机理：上下文里任务目标被工具结果挤掉，agent 忘了"要干什么"，只能重复最"像在干活"的动作。检测：调用签名/结果哈希去重 + 轮次预算；止住：goal 重注入（每轮带任务摘要）、强制摘要压缩、熔断转人工。能主动提到"这是上下文管理问题不是模型能力问题"= 真踩过坑 |
| **危险信号** | 只答"换个更强的模型"；说不出检测与止住两个层面的区别；不提上下文/记忆层 |

### C5 SSE 流式中断类（本地复现不了）

| 栏目 | 内容 |
|------|------|
| **题面（口述）** | "SSE 流式回复在生产环境经常中途卡死，本地完全复现不了。给排查清单。" **（故意不说：网关架构/超时配置/心跳机制）** |
| **考察点** | 基建嗅觉：代理/网关层、超时与缓冲、心跳与断连重连 |
| **好答案的形状** | 先问：生产链路经过哪些代理/网关（Nginx/SLB/API 网关）？超时配置多少？有没有心跳？分层清单：网关缓冲（Nginx `proxy_buffering` 需关闭）→ 空闲超时（`proxy_read_timeout`）→ keepalive → 心跳/进度帧保活 → 断连重连（带 offset 续传）。知道"本地复现不了 = 环境差异，先对齐链路拓扑" |
| **危险信号** | 只答"加日志"就停；不问生产链路拓扑就开始给方案；不知道流式响应经过代理会缓冲 |

### C 类判卷四行为（汇总）

| # | 行为 | 判定 |
|---|------|------|
| 1 | 动手前先问澄清，还是直接开编 | 开编 = 危险信号（接元能力"编造流程"强减分） |
| 2 | 假设树是否 ≥3 个分支、有没有排序 | 单枝直奔 = 经验彩票，不是推理 |
| 3 | 每个假设的判别成本是否从便宜到贵 | 先看日志/抓报文 > 先重放 > 先加埋点/换模型 |
| 4 | 说到知识边界坦不坦白 | "没排过，但我会先看 X" = 加分；流畅编造 = 强减分 |

> "没排过这类故障"是中性的（❓未覆盖，按层级处理）；"不问澄清就开编"才是危险信号。

## 第六部分：面试官观察要点

### 加分信号 🟢

| 信号 | 含义 |
|------|------|
| 能清晰解释仿真系统的架构设计思路 | 系统建模能力可迁移 |
| 知道RLHF和PPO的关系 | 有知识迁移能力 |

| 能快速理解RAG/Agent等新概念 | 学习能力强 |
| 问了团队技术栈或项目相关问题 | 求职动机真实 |

### 减分信号 🔴

| 信号 | 含义 |
|------|------|
| 说不清自己项目的核心设计 | 可能只是跑了别人的代码 |
| 对AI完全无兴趣 | 只是为了找个实习 |
| 代码没有模块拆分/测试 | 工程化意识为零 |
| 间隔期支支吾吾 | 可能有隐瞒 |
| 只关心待遇/工作时长 | 动机不匹配 |
| 学术惯性极强（只想发论文） | 不适合工程化岗位 |

### E1 递归求二叉树最大深度（本题库基础）

**题干与输入输出**

给定二叉树根节点 `root`，请手写递归函数 `max_depth(root)`，返回从根节点到最远叶子节点的路径上**节点数**。空树深度为 `0`，仅根节点的树深度为 `1`；不是按边数计深度。节点包含整数 `val`、左孩子 `left` 和右孩子 `right`，空孩子为 `None`，不得修改树。

题面用层序数组展示输入：按队列逐个取出非空节点，为其依次读取左、右孩子；`null` 表示空孩子且不入队，末尾空孩子可省略，`[]` 为空树。函数实际接收已构造的节点，不要求实现数组解析。

**约束**：节点数 `0 ≤ n ≤ 10^4`；树高 `h ≤ 200`；节点值在 `[-10^9, 10^9]` 内，可重复；输入是无环且不共享子节点的合法二叉树。面试运行环境应支持至少 201 层函数调用，避免将环境栈限制当作本题算法错误。

**正常及边界测试（预期均按节点数）**

| 类型 | 输入（层序数组或构造说明） | 预期输出 |
|------|--------------------------|----------|
| 正常：两侧深度不同 | `[3, 9, 20, null, null, 15, 7]` | `3` |
| 边界：空树 | `[]` | `0` |
| 边界：单节点且值为零 | `[0]` | `1` |
| 边界：仅右孩子链 | `[1, null, 2, null, 3, null, 4]` | `4` |
| 边界：重复值、左右子树 | `[1, 1, 1]` | `2` |
| 规模边界：200 个节点组成左链 | 节点值均为 `0` | `200` |
| 规模边界：10000 个节点的完全二叉树 | 层序填入 10000 个 `0` | `14` |

**参考解法与复杂度（面试官用）**

空节点返回 `0`；非空节点分别求左右子树深度，取较大值再加 `1`。每个节点访问一次，时间 `O(n)`，递归栈空间 `O(h)`（空树为 `O(1)`）；空间不能漏掉调用栈。

```python
class TreeNode:
    def __init__(self, val: int = 0, left: "TreeNode | None" = None,
                 right: "TreeNode | None" = None) -> None:
        self.val = val
        self.left = left
        self.right = right


def max_depth(root: TreeNode | None) -> int:
    if root is None:
        return 0
    return 1 + max(max_depth(root.left), max_depth(root.right))
```

**两级提示（逐级给，不同时展示）**

1. 一级：先分别画出空树、单节点树，确定递归什么时候停止以及返回什么。
2. 二级：假设已知道左、右子树的深度，当前节点只需取两者较大值并加上自己这一层。

**变式追问**：如果扩大输入规模限制，树可能退化为十万层链，如何改为显式栈或队列，避免递归栈溢出？

### E2 两数之和（本题库基础）

**题干与输入输出**

给定整数数组 `nums` 和整数 `target`，请手写函数 `two_sum(nums, target)`，返回两个不同位置的**下标** `[i, j]`，满足 `i < j` 且 `nums[i] + nums[j] == target`。下标从 `0` 开始，不能重复使用同一个元素；没有解返回 `[]`，有多个解时返回任意一组合法下标即可。不得修改输入数组。

**约束**：`0 ≤ len(nums) ≤ 10^4`；`nums` 元素及 `target` 都在 `[-10^9, 10^9]` 内；允许重复值、负数、零，不保证有解或唯一解。先完成正确实现，再讨论能否用额外空间将两层枚举优化为一次扫描。

**正常及边界测试**

| 类型 | 输入 | 预期输出 |
|------|------|----------|
| 正常：唯一解 | `nums=[2, 7, 11, 15], target=9` | `[0, 1]` |
| 边界：重复值来自不同下标 | `nums=[3, 3], target=6` | `[0, 1]` |
| 边界：负数与零 | `nums=[-3, 0, 3], target=0` | `[0, 2]` |
| 边界：两个零 | `nums=[0, 0], target=0` | `[0, 1]` |
| 边界：空数组 | `nums=[], target=0` | `[]` |
| 边界：不能用同一元素两次 | `nums=[3], target=6` | `[]` |
| 边界：无解 | `nums=[1, 2, 3], target=7` | `[]` |
| 边界：多解 | `nums=[1, 2, 3, 4], target=5` | `[0, 3]` 或 `[1, 2]`；参考实现返回 `[1, 2]` |
| 数值边界 | `nums=[-1000000000, 1000000000], target=0` | `[0, 1]` |
| 规模边界 | `nums=[0, 1, ..., 9999], target=19997` | `[9998, 9999]` |

**参考解法与复杂度（面试官用）**

用哈希表保存此前见过的“值 → 下标”。扫描当前元素时，**先查补数，再存当前值**，保证不重复使用当前下标。允许覆盖重复值对应的旧下标，因为只要求任一合法解。通常哈希操作均摊 `O(1)`，总时间期望 `O(n)`、额外空间 `O(n)`；若哈希严重退化，最坏时间可达 `O(n²)`。两层枚举为时间 `O(n²)`、额外空间 `O(1)`，记录实现与优化过程，不要求直接背出哈希解。

```python
def two_sum(nums: list[int], target: int) -> list[int]:
    seen: dict[int, int] = {}
    for j, value in enumerate(nums):
        complement = target - value
        if complement in seen:
            return [seen[complement], j]
        seen[value] = j
    return []
```

**两级提示（逐级给，不同时展示）**

1. 一级：固定当前数后，还缺哪个数才能得到目标？之前看过的数能否保存下来，避免每次重新扫描？
2. 二级：哈希表中保存值及其下标；先查 `target - 当前值`，没找到才把当前值存入表，想想 `[3]` 和 `[3, 3]` 的区别。

**变式追问**：如果数组保证升序，怎样用双指针在 `O(n)` 时间、`O(1)` 额外空间完成同样的下标查询？

### E3 有效括号（本题库基础）

**题干与输入输出**

给定字符串 `s`，仅包含 `(`、`)`、`[`、`]`、`{`、`}` 六种字符。请手写函数 `is_valid(s)` 返回布尔值：每个右括号都必须与此前**最近一个尚未匹配的左括号**配对，且二者类型相同，最后没有剩余左括号。空串视为有效；只统计各类括号数量相等不够。

**约束**：`0 ≤ len(s) ≤ 10^4`；不含空格、字母或其他字符，不必处理题设范围外的输入。输出为语言原生布尔值；表中用 `true` / `false` 表示。

**正常及边界测试**

| 类型 | 输入 `s` | 预期输出 |
|------|----------|----------|
| 正常：多组相邻括号 | `"()[]{}"` | `true` |
| 正常：多层嵌套 | `"{[()]}"` | `true` |
| 边界：空串 | `""` | `true` |
| 边界：错类型 | `"(]"` | `false` |
| 边界：数量相等但交叉 | `"([)]"` | `false` |
| 边界：右括号先出现 | `")("` | `false` |
| 边界：仅一个右括号 | `"]"` | `false` |
| 边界：剩余左括号 | `"(()"` | `false` |
| 规模边界：最大嵌套 | 5000 个 `(` 后接 5000 个 `)` | `true` |
| 规模边界：全部未闭合 | 10000 个 `(` | `false` |

**参考解法与复杂度（面试官用）**

左括号入栈；右括号必须匹配栈顶，否则立即返回 `False`。扫描结束还须检查栈为空。每个字符至多入栈、出栈各一次，时间 `O(n)`，额外空间 `O(n)`（全部为左括号时达到上界）。

```python
def is_valid(s: str) -> bool:
    pairs = {')': '(', ']': '[', '}': '{'}
    stack: list[str] = []
    for char in s:
        if char in '([{':
            stack.append(char)
        elif not stack or stack.pop() != pairs[char]:
            return False
    return not stack
```

**两级提示（逐级给，不同时展示）**

1. 一级：对比 `"([])"` 和 `"([)]"`，数量相同但结果不同；一个右括号应该先匹配哪一个尚未关闭的左括号？
2. 二级：用后进先出的栈保存左括号；遇到右括号检查栈是否为空、栈顶类型是否匹配，最后还要检查是否有剩余。

**变式追问**：若函数改为返回第一个无法匹配的右括号下标，结束时仍有左括号则返回 `len(s)`，完全有效返回 `-1`，核心代码需怎样调整？

### E4 合并区间（本题库中等）

**题干与输入输出**

给定整数闭区间列表 `intervals`，每项为 `[start, end]`。请手写函数 `merge_intervals(intervals)`，合并所有重叠区间，返回按起点升序排列、互不重叠且覆盖范围与输入相同的闭区间列表。**端点相同算重叠**，如 `[1, 4]` 与 `[4, 5]` 合并为 `[1, 5]`；`[1, 2]` 与 `[3, 4]` 不合并，不能因整数相邻就合并。空列表返回 `[]`；不得修改原列表及其内部区间。

**约束**：`0 ≤ len(intervals) ≤ 10^4`；每项恰有两个整数，`-10^9 ≤ start ≤ end ≤ 10^9`；允许无序、重复、完全包含及零长度区间。可调用标准排序 API，但合并循环必须手写。

**正常及边界测试**

| 类型 | 输入 `intervals` | 预期输出 |
|------|------------------|----------|
| 正常：部分重叠 | `[[1, 3], [2, 6], [8, 10], [15, 18]]` | `[[1, 6], [8, 10], [15, 18]]` |
| 边界：无序且端点接触 | `[[4, 5], [1, 4]]` | `[[1, 5]]` |
| 边界：空列表 | `[]` | `[]` |
| 边界：单个零长度区间 | `[[2, 2]]` | `[[2, 2]]` |
| 边界：重复、包含、同起点 | `[[1, 4], [1, 4], [1, 2], [2, 3]]` | `[[1, 4]]` |
| 边界：链式重叠 | `[[1, 2], [2, 3], [3, 4]]` | `[[1, 4]]` |
| 边界：整数相邻但不重叠 | `[[1, 2], [3, 4]]` | `[[1, 2], [3, 4]]` |
| 边界：负数、零与包含 | `[[-3, -1], [-1, 2], [0, 0]]` | `[[-3, 2]]` |
| 数值边界：单个大区间 | `[[-1000000000, 1000000000]]` | `[[-1000000000, 1000000000]]` |
| 规模边界：全部重复 | 10000 个 `[1, 1]` | `[[1, 1]]` |

**参考解法与复杂度（面试官用）**

先按起点排序，再顺序扫描。当前起点大于结果中最后一个区间的终点时新增区间，否则只把最后终点更新为两者较大值，避免被包含区间缩短结果。用新列表保存输出端点，不修改输入。时间 `O(n log n)`（扫描 `O(n)`）；本参考实现的排序新列表及排序辅助空间合计 `O(n)`，结果空间 `O(n)`，因此总额外空间 `O(n)`，不宣称原地常量空间。

```python
def merge_intervals(intervals: list[list[int]]) -> list[list[int]]:
    merged: list[list[int]] = []
    for start, end in sorted(intervals, key=lambda item: item[0]):
        if not merged or start > merged[-1][1]:
            merged.append([start, end])
        else:
            merged[-1][1] = max(merged[-1][1], end)
    return merged
```

**两级提示（逐级给，不同时展示）**

1. 一级：如果先按起点排序，扫描当前区间时，是否还需回头比较所有已处理区间？
2. 二级：只比较结果中的最后一个区间；当前起点 `≤` 最后终点时合并，终点取 `max`，否则开始新区间。

**变式追问**：如果输入改为半开区间 `[start, end)`，规定仅有非空交集时才合并，应如何改变端点比较，并处理 `[x, x)` 空区间？
