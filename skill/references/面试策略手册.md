## 第一部分：面试前分析策略

### 1.1 简历预分析（面试前完成）

拿到简历后，按以下5个维度做结构化预分析：

#### （1）职业轨迹扫描

画出候选人的完整时间线，标注每个阶段的**核心方向**：

```
时间 | 公司 | 岗位 | 核心方向 | 与JD相关度(高/中/低)
```

重点关注：
- **AI实际从业年限**：很多人写"10年研发经验"，但AI相关可能只有1-2年
- **转型节点**：什么时候开始做AI？是主动转型还是被动转岗？
- **公司背景验证**：大厂/创业公司/央企？不同背景的人技术深度差异很大

#### （2）项目真实性预判

对简历中每个核心项目，面试前准备3个层次的验证问题：

| 层次 | 问题类型 | 目的 |
|------|----------|------|
| **L1 做了什么** | 项目的业务背景、你负责什么、用了什么技术 | 验证参与度 |
| **L2 怎么做的** | 技术选型理由、架构设计思路、数据流是什么样的 | 验证技术深度 |
| **L3 为什么这么做** | 为什么不用方案B？遇到什么难点？怎么评估效果？ | 验证真实理解和决策能力 |

**红旗信号**（简历中可能注水的标志）：
- 只有项目列表，没有个人贡献描述
- 量化指标看似很高但缺乏baseline对比（如"准确率98%"——从多少提升到98%？）
- 用了热门技术栈但未说明具体使用场景
- 角色描述模糊（"参与"、"负责"、"主导"是三个完全不同的层级）

#### （3）量化指标解读

简历中出现的每一个量化指标，都要标注：
- ✅ **有baseline对比**（如"从80%提升至98%"）
- ⚠️ **有数字但无baseline**（如"准确率达98%"——原来多少？）
- ❌ **模糊指标**（如"显著提升"、"大幅优化"）

#### （4）技术栈覆盖度评估

对照JD核心技术能力要求，评估候选人技术栈的覆盖情况：

| JD核心能力 | 覆盖标记 |
|-----------|----------|
| 架构能力（分布式/微服务） | 🟢深度 / 🟡了解 / 🔴缺失 |
| 全栈技术理解（Redis/MQ/MySQL） | 🟢深度 / 🟡了解 / 🔴缺失 |
| AI工程化（智能体/LLM/RAG/函数调用） | 🟢深度 / 🟡了解 / 🔴缺失 |
| 模型训练/微调（SFT/DPO/蒸馏） | 🟢深度 / 🟡了解 / 🔴缺失 |
| 问题解决能力（性能优化/架构重构） | 🟢深度 / 🟡了解 / 🔴缺失 |

#### （5）联网验证

对关键信息做联网搜索验证：
- 论文：ACL Anthology / Google Scholar 搜索作者名
- 专利：Google Patents 搜索专利号
- 开源贡献：GitHub 搜索用户名
- 公司背景：天眼查/企查查
- 书籍/课程：豆瓣/极客时间验证
- 技术博客：个人网站/知乎/CSDN

## 第二部分：面试问题池

### 2.1 AI工程化核心能力

#### RAG（检索增强生成）

| # | 问题 | 考察点 | 期望回答要素 |
|---|------|--------|-------------|
| R1 | 你做RAG的完整数据流是什么样的？从用户提问到返回答案 | 闭环思维 | 查询→召回→重排→生成→后处理，每一步的技术选型 |
| R2 | 向量模型用的什么？为什么选这个？有没有做过模型评测对比？ | 模型选型能力 | 至少知道text-embedding-3-large、bge-m3、jina-embeddings等主流模型的优劣势 |
| R3 | 文档分块策略是什么？为什么？ | 分块策略理解 | 按字符/按段落/语义分块/递归分块，各自的优缺点 |
| R4 | 召回阶段是怎么做的？向量检索还是混合检索？ | 检索策略 | 向量相似度 + BM25关键词检索的混合策略，及各自的适用场景 |
| R5 | 阈值怎么取的？有没有量化标准？ | 评估方法论 | 不期望完美答案，但要有系统性思路，而非"纯靠调" |
| R6 | RAG的幻觉问题怎么解决？ | 工程化方案 | 提示词约束、溯源引用、后校验Agent、多轮检索、RAGAS评估 |
| R7 | embedding模型和re-ranker模型的区别？输入输出分别是什么？ | 核心概念 | embedding：文本→向量（检索用）；re-ranker：query+doc→相关性分数（精排用） |
| R8 | cosine相似度和点积的区别？应用上有什么区别？ | 基础数学 | cosine只看方向（归一化后），点积考虑模长；归一化向量上等价 |
| R9 | BM25和编辑距离了解吗？ | 检索基础 | BM25：基于词频的统计检索；编辑距离：字符串相似度 |
| R10 | 如果召回结果中有很多相似文档，怎么去重/过滤？ | 工程经验 | MMR（最大边际相关性）、聚类去重、相似度阈值 |

| A5 | 多Agent之间怎么通信？协调机制是什么？ | 系统设计 | 共享状态、消息传递、HTTP/gRPC、事件驱动 |

#### Prompt工程

| # | 问题 | 考察点 | 期望回答要素 |
|---|------|--------|-------------|
| P1 | 你写提示词有什么技巧？ | Prompt基本功 | 结构化（角色/任务/约束/示例）、CoT、Few-shot |
| P2 | 提示词大概多长？怎么迭代的？ | 实战经验 | 从短到长的迭代过程、A/B测试、回归测试 |
| P3 | 如果提示词明确要求了"基于知识库回答"但模型还是编造，怎么办？ | 工程化方案 | 提示词是第一层约束但不够：加溯源要求、后校验、降低温度、换用约束解码 |

| # | 问题 | 考察点 | 期望回答要素 |
|---|------|--------|-------------|

### 2.2 模型训练/微调

| # | 问题 | 考察点 | 期望回答要素 |
|---|------|--------|-------------|
| M1 | SFT和DPO的区别？ | 微调原理 | SFT：监督学习，学习输入→输出映射；DPO：偏好对齐，学习人类偏好排序 |

### 2.5 量化评估意识（贯穿全场）

**关键追问**（几乎适用于任何项目）：

```
Q1: 你做之前的效果是什么样的？（baseline）
Q2: 你做之后的效果是什么样的？（结果）
Q3: 这个提升是怎么测量出来的？（评估方法）
Q4: 有没有对照组？（科学性）
Q5: 如果现在让你重新做，有什么可以改进的？（反思）
```

## 第三部分：面试执行策略

### 3.1 面试节奏设计（约45-60分钟）

| 阶段 | 时长 | 内容 | 目的 |
|------|------|------|------|
| **开场** | 2min | 自我介绍 + 候选人自我介绍 | 破冰，观察表达能力 |
| **项目深挖** | 15-20min | 选1-2个核心项目，L1→L2→L3层层追问 | 验证技术深度和真实理解 |
| **技术原理** | 10-15min | 从项目中引申出技术概念追问 | 验证基础知识扎实度 |
| **场景题** | 10-15min | 给一个开放性场景，考察系统设计能力 | 验证架构思维和闭环能力 |
| **反问** | 3-5min | 候选人提问 | 观察关注点（技术/待遇/团队） |

### 3.2 追问方法论

核心原则：**从具体到抽象，从做了什么到为什么这么做**

```
第一层：你做了什么？
  ↓
第二层：怎么做的？（技术选型、架构设计、数据流）
  ↓
第三层：为什么这么做？（为什么不用方案B？）
  ↓
第四层：怎么评估的？（baseline是什么？指标怎么定的？）
  ↓
第五层：有什么不足？如果重来会怎么改？
```

**从候选人B面试中提炼的有效追问模式**：

1. **链式追问**（从一个点深入到原理层）：
   - "你做了RAG？"→"向量模型用的什么？"→"为什么选这个？"→"cosine和点乘的区别？"→"应用上有什么区别？"
   
2. **闭环追问**（要求完整数据流）：
   - "能完整的讲一下数据流吗？从用户提问到最后的闭环"
   
3. **反例追问**（挑战方案合理性）：
   - "7B模型做不了意图识别吗？不调的话做不了吗？"
   - "退出就不做了吗？这个事谁来处理？"
   
4. **量化追问**（要求可衡量）：
   - "有没有量化指标？"
   - "微调前有没有baseline？"
   - "怎么衡量你的工作价值？"
   
5. **提示性追问**（给方向但不给答案）：
   - "给你个提醒，你可以看看智能体的一些构建策略"
   - 在候选人卡住时给方向，看他的学习能力和思维弹性

### 3.3 评分维度

每个候选人按以下维度打分（1-5分）：

| 维度 | 权重 | 1分 | 3分 | 5分 |
|------|------|-----|-----|-----|
| **AI工程化深度** | 30% | 会用框架但不懂原理 | 能独立设计RAG/Agent方案 | 能解决幻觉/评估等深层问题 |
| **架构设计能力** | 25% | 只做过单模块 | 能设计完整系统架构 | 能处理高并发/分布式等复杂场景 |
| **模型理解** | 15% | 只调API | 会微调/蒸馏 | 理解训练原理，能优化模型效果 |
| **量化评估意识** | 15% | 无量化意识 | 有数字但无baseline | 有完整的baseline→改进→评估闭环 |
| **独立负责能力** | 10% | 需要全程指导 | 能在指导下完成 | 能独立从0到1闭环 |
| **学习能力** | 5% | 只用熟悉的技术 | 能快速学新技术 | 能将新技术与业务结合 |

> **软性素质（按 JD 清单，AC-8 分层服从）**：上表是本岗位（专家岗）的**知识层**评分维度。**软性素质**不在此表另起分数，而是按 Step 2 产出的「JD 软性素质要求清单」逐项做「要求 × 表现」对比（见 `软性素质要求×表现对比-示例.md`），映射到现有元能力五项（自知力 / 态度-可管理性 / 可引导性 / 沟通 / 诚实度）。其权重与红线随层级变化，**取值派生自 SKILL.md §分层标尺（SoT）**：
> - **专家岗**：软性素质权重低（看深度）；中权重软性素质缺失 = 提示培养 / 搭配，非一票否决。
> - **外包 / 初级岗**：「可管理性 / 可引导性」权重 40-50%，缺失 = 强减分。
> - **实习生岗**：「诚实度」一票否决。
>
> 判定三态：✅有证据支撑 / ❌缺失（真实缺口，进风险点）/ ❓存疑（中性，不扣分）。每条判定引用原文，无原文不下结论。

### 3.4 定级标准

| 等级 | 描述 | 对应薪资范围参考 |

## 第五部分：常见候选人类型识别

### 5.1 "广度型"（候选人B类型）

**特征**：
- 简历项目多、技术栈广、有内容输出（书/博客/演讲）
- 什么都用过、什么都知道一些
- 往深了一问就卡住

**面试策略**：
- 选取1-2个核心项目，L3追问到底
- 重点考察：有没有一个方向是真正深入的
- 警惕：简历丰富 ≠ 技术深厚

### 5.2 "大厂螺丝钉型"

**特征**：
- 大厂背景，做过高并发/高可用系统
- 但只负责其中一个模块，缺乏全局视野
- 对"为什么这么做"答不上来

**面试策略**：
- 追问架构全貌，不只是他负责的模块
- 场景题考察系统设计能力
- 重点考察：能否从模块视角上升到系统视角

### 5.3 "学术转型型"

**特征**：
- 有论文、有算法基础
- 但工程落地经验少
- 写论文和做产品的思维模式不同

**面试策略**：
- 重点考察工程化能力：怎么部署、怎么监控、怎么处理线上问题
- 场景题考察产品思维
- 重点考察：能否把算法能力转化为业务价值

### 5.4 "包装过度型"

**特征**：
- 简历写得很漂亮，量化指标很多
- 但细节经不起追问
- 关键词堆砌

**面试策略**：
- 对每个量化指标追问baseline
- 要求完整数据流描述
- L3追问（为什么这么做）最能暴露

### 5.5 "全链路闭环型"

**特征**：
- 算法有顶会论文/专利背书，不是调参工，而是有原创性贡献
- 工程有生产级系统落地（高可用、高吞吐、完整的部署和监控体系）
- 管理有平台级架构视野（从数据基建→模型矩阵→智能体生态→业务效果量化）
- 量化意识贯穿始终：所有项目均有明确的 baseline→改进→结果 对比链
- 产学研一体：论文、专利、软著、业务落地形成闭环

**与其他类型的区分**：
- vs "广度型"：不只广，核心方向有论文级别的深度
- vs "大厂螺丝钉型"：是从0到1的负责人，有全局架构视野而非单一模块
- vs "学术转型型"：学术强但工程同样扎实，不存在"只会写论文不会落地"的问题
- vs "包装过度型"：量化指标有baseline对比，论文/专利可联网验证，经得起追问

**面试策略**：
- 重点不是验证真实性（经得起追问），而是评估**天花板在哪里**
- 考察维度应升级：从"能不能做"到"能不能带队做"
  - 技术选型的trade-off判断力（为什么不用方案C？）
  - 团队管理与跨部门协同能力（怎么协调多个团队？遇到阻力怎么解决？）
  - 技术路线规划能力（未来6-12个月的技术roadmap是什么？）
  - 对行业趋势的判断力（HR Tech/AI领域的下一步方向？）
- 场景题应给更高复杂度的设定（多系统协作、成本与效果平衡、技术债治理等）
- 关注短板：是否有明显的能力盲区（如后端架构偏某一语言栈、团队管理经验不足等）
- 这类候选人面试更像是**双向选择**，需要同时展示团队的技术实力和发展空间
