# 面试评价 — 简略版

**产物 schema（Step 6 横向输出 · 字段 + 取值域）**

| 字段 | 取值域 |
|------|--------|
| 层级总览（分区） | `list[{层级分区, 候选人, 整体水位, 推进建议}]`（跨层级**绝不**同表对比） |
| 决策视图（同分区内） | per-候选人：{评级, 建议, 核心价值, 核心风险} + 软性素质逐项 `{JD要求: ✅/❌/❓}` |
| 单人明细（可选） | per-候选人：亮点 / 短板 / 综合 |
| 判定符号 | ✅ / ❌ / ❓（**禁用 🟡**；🟡 仅 Step 3 简历信号强度） |

## 候选人C | 后端架构师/AI工程化专家 | 评级：中高级

**核心结论**：建议推进，定位**智能体开发核心骨干**

**亮点**：
- DITR模式自研（在DeepSeek R1时代自己用XML标签实现function call），双链路架构独立设计（主链路+子智能体异步生成+卡片占位），有真实的Agent架构创新力
- 后端底子好：Golang大厂（某头部内容平台），QPS 60k
- 技术热情真实：自己花200/天用Claude Code，在家用OpenClaw连小米摄像头做AI应用
- 自我认知好：坦诚"模型底层不了解"、"非科班"

**短板**：
- 代码质量粗糙：倾向于新增模块而非重构，需要团队建立review机制来补
- 模型层空白：没做过训练，embedding/reranker/cosine答不上来
- 框架层偏执行：PEER/DOE等核心框架非他设计

**综合**：能独立设计Agent架构，出活快，后端底子扎实。代码质量问题可通过review机制解决，模型层可由团队补。是团队里能扛活的核心力量。

## 候选人D | 后端架构师/AI工程化专家 | 评级：中级

**核心结论**：可以考虑推进，定位**初级AI应用开发，需培养**

**亮点**：
- RAG项目参与度不低：切分策略按内容类型分三区、混合检索有权重分配、badcase驱动的优化闭环，有实战积累
- 学历好：某985高校本硕
- 某头部科技公司4年有大厂规范
- 在积极学习前沿技术，会议纪要场景题能参考Claude Code的压缩机制

**短板**：
- 工作年限不满足JD（4年 vs 5年+）
- embedding输入说成one-hot，底层原理理解不够
- 架构能力欠缺，自己定位"快速复现demo"
- 简历上的术语（双飞轮治理等）面试时讲不清楚

**综合**：RAG有实战经验，学习能力强，但需要架构师指导。如果团队有培养空间，可以作为潜力股培养。

## 横向决策视图（先按层级分区 → 同分区按同一份 JD 清单对齐）

> AC-6 机械两步法：① 先按层级分区（跨层级**绝不**同表对比，标尺不同）；② 同分区内按同一份 JD 软性素质要求清单逐项对齐。判定三态 ✅ / ❌ / ❓（❓ 含存疑与未覆盖，均中性不扣分），每条引用原文，**判定列禁用 🟡**（🟡 只合规于 Step 3 简历证据"信号强度"列）。完整格式见 `软性素质要求×表现对比-示例.md`。

### 第 ① 步：层级总览（先分区）

| 层级分区 | 候选人 | 整体水位 | 分区推进建议 |
|---------|--------|---------|------------|
| **专家 / 正式岗**（后端架构师 / AI 工程化专家） | C、D、B | C 中高级 / D 中级 / B 中高级（不推进） | C 推进核心骨干；D 培养型；B 不推进 |
| 外包 / 初级岗 | （本期无） | — | — |
| 实习生岗 | （本期无） | — | — |

> 本期三人均为同一专家岗，落在同一分区；若候选池跨层级，先在此表分区、再进各分区明细，**绝不在一张表里混比不同层级**。

### 第 ② 步：专家岗分区 — 统一决策视图（知识层 + 软性素质合并）

| 决策维度 | 候选人C | 候选人D | 候选人B（已面） |
|---------|--------|--------|---------------|
| **评级** | 中高级 | 中级 | 中高级 |
| **建议** | **推进，核心骨干** | **可推进，培养型** | 不推进 |
| **核心价值**（知识层） | Agent架构创新+快速出活 | RAG实战+学习潜力 | 广度覆盖 |
| **核心风险**（知识层） | 代码质量+模型层空白 | 经验浅+原理薄弱 | 各方面偏浅，无法独立负责 |
| ── 软性素质（同一份 JD 清单，✅/❌/❓） ── | | | |
| 沟通协作（高） | ✅ 能讲清 DITR 双链路架构（面试原文） | ❓ 表达绕、术语堆砌 | ❌ 答非所问、需重复问题 |
| 责任心 / Ownership（高） | ✅ "自己花200/天用Claude Code"自驱 owner | ❓ 角色多为"参与"非"主导"（弱 / 部分证据） | ❓ 简历角色模糊 |
| 学习能力（中） | ✅ 主动学 OpenClaw 连小米摄像头做 AI 应用 | ✅ 会议纪要场景题参考 Claude Code 压缩机制 | ❓ 知识停留在表面（单点弱证据） |
| 诚实度 / 诚信（红线） | ✅ 坦诚"模型底层不了解""非科班" | ❓ 简历有水分（双飞轮治理讲不清，待验指标含义 + baseline） | ❌ 疑似边搜边答 |
| 自知力 / 自我认知（中） | ✅ 主动暴露短板 | ❓ 只讲亮点 | ❌ 装懂、包装 |
| 可引导性 / 可管理性（中） | ❓ 倾向新增模块而非重构（单点，需 review 机制引导） | ✅ 能参考提示调整方案 | ❌ 给提示仍犟 |

**决策小结**：一张视图同时看知识层（评级 / 价值 / 风险）与软性素质——C 诚实度 / 自知力 / 沟通证据扎实（适合核心骨干，配 review 机制补可引导性）；D 学习能力有证据但 ownership 偏弱、简历有水分（培养型）；B 诚实度红线存疑、可引导性弱（不推进）。**软性素质服从分层标尺（SoT），不另起统一分数，也不替代知识层评测。**
