# 软性素质要求 × 表现 逐项对比 — 林沐（虚构示例）

> 虚构示例：本文件与 `examples/` 下的 JD / 简历 / 面试记录同属虚构「星澜科技 / 林沐」场景，仅供演示 skill 的三段闭环（JD 要求挖掘 → 跨资料证据挖掘 → 逐项对比）。与任何真实人物 / 公司无关。
>
> 词典归一化依据：`references/软性素质词典-参考.md`（O*NET Work Styles 主干，仅做归一化，零心理测评）。

**产物 schema（Step 2 / 3 / 6 软性素质输出 · 字段 + 取值域）**

| 子产物 | 字段 + 取值域 |
|--------|------------|
| ① JD 要求清单（Step 2） | `list[{#, 软性素质, 权重: 高/中/红线, 显式/隐式, JD原文出处, 定义, 考察提示}]`（隐式须注推断依据） |
| ② 简历证据（Step 3） | `list[{JD要求(权重), 简历证据(原文), 信号强度: 🟢强 / 🟡中 / 🔴缺失 / ❓存疑, 映射元能力, 待面试验证}]` |
| ③ 要求×表现对比（Step 6） | `list[{JD要求, 权重, JD出处, 简历证据, 面试证据(原文), 综合判定: ✅ / ❌ / ❓(未覆盖·存疑), 置信: 高/中/低}]` |
| ④ 横向对比 | `list[{JD要求(权重), per-候选人: ✅/❌/❓}]`（先按层级分区） |
| ⑤ 证据覆盖校准（Step 7） | `list[{反馈信号, 校准动作}]`（零证据 → 反哺 Step 5） |

## ① Step 2 产出：JD 软性素质要求清单（JD 驱动，六要素）

> 来源 JD：`examples/jd/后端架构AI工程化-示例JD.md`。每项含 名称 / 定义 / JD 原文出处 / 显式 or 隐式 / 权重 / 考察提示。隐式项强制注明「推断 + 依据」，不臆造；权重来自 JD 表述力度（精通 > 熟悉 > 了解）与排序位置。

| # | 软性素质 | 权重 | 显式/隐式 | JD 原文出处 | 定义（词典归一化） | 考察提示 |
|---|---------|------|----------|------------|-------------------|---------|
| 1 | 沟通协作 | 高 | 显式 | 「主导技术方案评审、核心代码规范、技术沉淀与团队能力建设，推动 AI + 后端研发流程标准化」 | 把复杂讲简单、跨角色对齐信息（词典 §1） | 能否讲清 RAG 数据流；是「对齐方」还是「各做各的」 |
| 2 | 责任心 / Ownership | 高 | 隐式 | 「主导企业级应用系统后端整体架构设计」「加分项：主导过……从 0 到 1 落地全流程经验」（推断：暗含独立负责、端到端兜底） | 对结果负责、不甩锅（词典 §2） | 项目里是「主导」还是「参与」；线上出事谁来兜底 |
| 3 | 学习能力 | 中 | 隐式 | 「运用 Spec Driven 等 AI 原生软件开发方式」「深入理解……大模型调用链路」（推断：需持续跟进前沿） | 快速理解新概念并迁移（词典 §4） | 给提示后能否跟上；最近在学什么 |
| 4 | 抗压与坚韧性 | 中 | 隐式 | 「性能 / 稳定性优化」「异常治理全流程落地」（推断：高并发 / 线上故障场景需抗压） | 压力下稳定输出（词典 §5） | 有无线上故障 / 紧急救火经历（引原文） |
| 5 | 诚实度 / 诚信 | 红线 | 隐式 | 任何岗位默认（接现有诚信红线；专家岗简历打折直接降级） | 实事求是、不编造（词典 §6） | 量化有无 baseline；被拆穿后是否狡辩 |
| 6 | 自知力 / 自我认知 | 中 | 隐式 | 「深入理解 AI 智能体工作机制」（推断：「深入理解」要求能区分懂与不懂） | 主动暴露短板、不包装（词典 §7） | 会不会主动说「这块没做过」；项目短板能否答出 |
| 7 | 可引导性 / 可管理性 | 中 | 隐式 | 「技术团队与研发效能提升」「推动标准化」（推断：需可协作、可引导） | 听得进反馈、能调整（词典 §8） | 给提示 / 方向后能否跟上并调整 |

> 说明：诚实度对专家岗为「简历打折即降级」的红线级要求；对外包岗为「被拆穿后诚实=可接受」，对实习生岗为「一票否决」。本例为专家岗，故标「红线」。

## ③ Step 6 产出：软性素质要求 × 表现 逐项对比（核心）

> 面试证据来源：`examples/transcript/林沐-面试记录-示例.txt`。每项含 JD 要求 / 权重 / JD 出处 / 简历证据 / 面试证据（原文）/ 综合判定 / 置信。判定引用原文，无原文不下结论。

| JD 要求 | 权重 | JD 出处 | 简历证据 | 面试证据（原文） | 综合判定 | 置信 |
|---------|------|--------|---------|-----------------|---------|------|
| 沟通协作 | 高 | 「主导技术方案评审 / 推动标准化」 | 「支撑客服与运营两个业务线」 | 「embedding 是把一段文本映射成一个向量……reranker 是输入一个 query 和一个 doc，输出一个相关性分数」（面试原文，把复杂讲简单） | ✅ 有证据支撑 | 高 |
| 责任心 / Ownership | 高 | 「主导……架构设计」「从 0 到 1」 | 项目 1「技术负责人（0→1 主导）」 | 「72% 是我们上线前用一批标注好的 query-doc 对做的离线评估」（面试原文，能说清自己主导项目的来龙去脉） | ✅ 有证据支撑 | 高 |
| 学习能力 | 中 | 「AI 原生软件开发方式」 | 简历未提最近在学什么 | 问选型理由时能迁移思考（「先用大模型加 Prompt 验证可行性……再收集数据微调一个小模型降本」），但**未直接探到学习意愿 / 最近在学什么** | ❓ 存疑（单点弱证据） | 低 |
| 抗压与坚韧性 | 中 | 「性能 / 稳定性优化」「异常治理」 | 简历无线上故障 / 紧急救火描述 | 面试全程未涉及线上故障 / 压力场景（**压根没探到，非问过还没有**） | ❓ 未覆盖 | 中 |
| 诚实度 / 诚信 | 红线 | 默认（专家岗） | 量化均有 baseline | 「LoRA 我自己没真正训过，只是了解概念……这块我确实没实操经验」（面试原文，被问到不会时坦诚承认，不编造） | ✅ 有证据支撑（态度正） | 高 |
| 自知力 / 自我认知 | 中 | 「深入理解」 | 自我评价「坦诚短板」 | 同上：主动承认 LoRA / 模型训练层短板，不包装 | ✅ 有证据支撑 | 高 |
| 可引导性 / 可管理性 | 中 | 「技术团队与研发效能提升」 | 简历层难提取 | 「一开始是拍的 0.7 / 0.3，后来我们在验证集上扫了几组，发现 0.6 / 0.4……recall 更高」（面试原文，给数据反馈后能调整决策） | ✅ 有证据支撑 | 中 |

### 判定规则（语义严格；与 SKILL.md 三态判定同步）

> "综合判定"列只能用这三个**符号**：✅ / ❌ / ❓（❓ 再按证据覆盖情况分两种语义）。不得用 🟡。

- **✅ 有证据支撑**：简历或面试有**原文**证据支持该要求，且元能力反应正向。
- **❌ 缺失（真实能力缺口 → 进风险点、按层级扣分）**：**已探查过**（Step 5 出过题 / 面试问到了该维度）仍**无对应证据**。只有"问过 / 探过还没有"才算 ❌。
- **❓ 未覆盖（证据覆盖缺口 → 中性不扣分，反哺 Step 5）**：**压根没探到**（没出题 / 面试全程未涉及该维度）。**禁止把"没问到"错判成"候选人没有"**——它只是这轮没覆盖，下轮补探查后才能升 / 降级。
- **❓ 存疑（中性不扣分，建议二面再验）**：探到了但证据**单点 / 模糊 / 矛盾**，不足以判定。
- **证据驱动**：每条判定引用原文；无原文不得下结论（沿用现有「无法验证 = 中性」原则）。
- **🟡 不是判定态**：🟢 / 🟡 / 🔴 只在 Step 3 简历证据的"信号强度"列出现（design §3.2 既定用法）；Step 6 判定若想表达"弱证据 / 部分"，归到 **❓存疑 / ❓未覆盖**，不要新造 🟡。

### 缺口与覆盖处理（按层级）

| 项 | 判定 | 权重 / 层级 | 处理 |
|--------|------|-----------|------|
| 抗压与坚韧性 | ❓ 未覆盖 | 中 / 专家岗 | **这轮压根没探到**（面试全程未涉及）= 证据覆盖缺口，**中性不扣分**；反哺 Step 5 下轮补「线上故障 / 紧急交付」探查题。**若下轮探查过仍无证据 → 升级为 ❌ 缺失**，按下下行处理 |
| （假设）抗压补探查后仍无证据 | ❌ 缺失 | 中 / 专家岗 | 专家岗中权重软性素质**真实缺口** → 提示「可培养 / 需搭配」，非一票否决；实习生岗「诚实度」缺失一票否决；外包岗「可引导性 / 可管理性」缺失为强减分（权重 40-50%） |
| 学习能力 | ❓ 存疑 | 中 / 专家岗 | 探到了但单点弱证据，**中性不扣分**；建议二面补「最近在学什么 + 迁移案例」探查 |

> 分层服从（AC-8）：本例为专家岗，软性素质权重低（看深度），中权重缺口不触发红线；**不另起全局统一分数**。注意区分：❓未覆盖是"没问到"（中性，反哺 Step 5），❌缺失是"问过还没有"（真实缺口，进风险点）。

## ④ Step 6 横向对比（先按层级分区 → 同分区按同一份 JD 清单对齐）

> AC-6 两步法：先按层级分区（跨层级**绝不**同表对比），再在同分区内按**同一份 JD 软性素质要求清单**逐项对齐。下表演示同分区（专家岗）内两人对齐；分区总览与多分区结构见 `候选人横向对比-示例.md`。不同岗位 / 不同层级不混比（沿用现有「禁止跨层级直接对比」）。

| JD 要求（权重） | 林沐 | 周屿（虚构） |
|----------------|------|------------|
| 沟通协作（高） | ✅ 能把 RAG 数据流讲简单（面试原文） | ❓ 表达绕、需面试官重复问题（面试原文） |
| 责任心 / Ownership（高） | ✅ 项目 1「0→1 技术负责人」+ 能说清来龙去脉 | ✅ 多个项目「主导」（简历原文） |
| 学习能力（中） | ❓ 单点弱证据，未探到学习意愿 | ✅ 「最近在学 X，因为它能解决 Y」（面试原文） |
| 抗压与坚韧性（中） | ❓ 全程未探到（覆盖缺口，反哺 Step 5） | ✅ 有一次线上故障复盘经历（面试原文） |
| 诚实度 / 诚信（红线） | ✅ 坦诚 LoRA 不会，量化有 baseline | ❌ 量化指标无 baseline，被拆穿后含糊 |
| 自知力 / 自我认知（中） | ✅ 主动承认短板 | ❓ 只讲亮点、避谈短板 |
| 可引导性 / 可管理性（中） | ✅ 给数据反馈后能调整 | ❓ 给提示后仍犟、拒绝调整 |

**横向小结**：林沐在诚实度 / 自知力 / 可引导性上证据扎实，抗压这轮未被探查到（❓未覆盖，反哺 Step 5，非真实缺口）；周屿 ownership 与抗压有证据，但诚实度（红线）存疑、可引导性弱。同一份 JD 清单下可直接对比「谁在哪个软性素质上有 / 缺证据」。

## ⑤ Step 7 产出：软性素质证据覆盖校准（闭环反哺）

| 反馈信号 | 校准动作 |
|----------|---------|
| 抗压与坚韧性：简历 + 面试全流程未探到（❓未覆盖，非真实缺口） | 反哺 Step 5 补「线上故障 / 紧急交付」探查题；标「证据覆盖缺口」；下轮探查过仍无证据才升级 ❌缺失 |
| 学习能力：Step 3 简历信号（存疑）与 Step 6 判定（存疑）方向一致 | 暂不校准预判模型；二面补探查后再评估 |
| 诚实度：Step 3 信号（量化有 baseline = 正向）与 Step 6 判定（坦诚不会 = 正向）一致 | 无偏差，预判模型可信 |
| 可引导性：Step 3 简历层难提取（存疑）→ Step 6 面试有正向证据 | 校准：该标签简历信号天生弱，后续预判对「简历层难提取」项不轻易标缺失，留待面试 |
