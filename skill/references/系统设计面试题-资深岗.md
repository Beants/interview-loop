# 系统设计面试题 — 资深岗（Step 5 参考）

> **设计输入（2026-09）**：对齐资深社招改革方向——资深岗面试**以系统设计为主体、算法只考思路/伪代码**（校招/实习保持原制，可手写代码）。系统设计题用真实工程经验才答得好：ACM 金牌但没上过生产的选手答不好，高水平资深工程师得心应手——这正是它成为资深岗主体的原因。
>
> **纪律**：题型配比派生自 SKILL.md §分层标尺（SoT）「面试题型配比」行，本文件不另立配比；评分沿用"证据驱动 + 元能力并行观察"——同一道题既出知识层证据、也出元能力证据。

## ① 出题模板（场景必须带真实约束，否则退化为背架构图）

```
[业务场景 2-3 句]
+ [规模数字：DAU / QPS / 数据量 / 延迟要求（P95/P99）]
+ [硬约束：预算 / 团队规模 / 已有系统 / 合规]

现场五问（候选人口头 + 白板/伪代码作答均可，不要求可运行代码）：
① 你会先澄清哪些需求假设？若关键假设不成立，方案怎么变？
② 给出架构与关键选型：≥2 个候选方案的对比与否决理由
③ 容量估算：写出估算过程（公式 + 数量级）
④ 两个最可能的故障模式与应对（降级/幂等/雪崩…）
⑤ 上线后第一步演进：v1 里你故意接受了哪些妥协，怎么偿还？
```

## ② 评分标尺（强信号 / 弱信号 / 红旗，逐项引用原文打标）

| 维度 | 强信号 ✅ | 弱信号 | 红旗 ❌ |
|------|----------|--------|--------|
| 需求处理 | 主动列出假设并说明"若假设不成立方案怎么变" | 直接开始画架构，假设隐含但自洽 | 无视题设数字，或擅自改规模 |
| 选型 | ≥2 个候选 + 否决理由清晰；提到团队/成本约束 | 单方案但理由具体 | 名词堆砌（K8s+服务网格+中台拉满）与题设规模无关 |
| 容量 | 有数量级正确的过程（写公式） | 只给结论数字无过程 | 数字与方案脱节（估完不用） |
| 故障 | 故障模式带真实踩坑细节（降级链路、幂等键、雪崩边界） | 只说"加监控告警" | 零故障意识 |
| 演进 | 能识别 v1 的临时妥协及偿还计划 | 泛泛"后续优化" | 宣称一步到位、永不需要重构 |

**元能力并行观察（一题双标尺）**：被追问"如果规模 ×10"时的反应（可引导性）、主动承认"这块我没做过，但我会这么查"（自知力）、把复杂取舍讲简单（沟通 L3-L4）——系统设计题是最自然的元能力载体，这些维度不必另出探测题。

## ③ 现场追问链（衔接「跨领域追问原则」）

五问的每一问都可向下追两层，形成探底链：

| 起点 | 第一追 | 第二追 |
|------|--------|--------|
| ① 假设 | "这条假设怎么验证？" | "验证成本太高时你怎么决策？" |
| ② 选型 | "被否方案在什么条件下反而更优？" | "团队没人会这个组件怎么办？" |
| ③ 容量 | "这个数字差一个数量级，方案哪部分先崩？" | "买不起这个配置怎么办？" |
| ④ 故障 | "这个故障你真踩过还是推测的？"（**分水岭题**——真实踩过的人有细节） | "事后加了什么机制？" |
| ⑤ 演进 | "为什么不现在就做？" | "拖延的代价怎么量化？" |

## ④ 示例题（AI 工程化岗，配合 Step 2 基准线）

> 你们要给一个 3000 人的制造企业做内部知识问答系统。现有 20 万篇文档（PDF/Word/扫描件混合），日活约 800 人，工作时段集中提问。预算只够 2 张 A10，要求首 Token P95 < 2s。IT 团队只有 3 个后端，没有算法工程师。
> 按五问作答，口头 + 白板/伪代码均可，**不要求可运行代码**。
>
> 考察锚点：扫描件 OCR 路由、Milvus Lite vs 服务器版取舍、embedding/reranker 分级、热点缓存与首 Token 优化、3 人团队运维边界——每个锚点都对应"真实工程经验才答得出"的判断点。

## ⑤ 算法思路题（降格使用，仅 JD 明确需要时）

**出题原则**：场景化（来自真实工程），问"怎么解"不问"写出来"。资深岗**不考手写无 bug 代码**——那是校招/实习题型。

**评分标尺：**

| 强信号 ✅ | 弱信号 | 红旗 ❌ |
|----------|--------|--------|
| 先问/声明数据规模与访问模式，再由规模选算法 | 直接给算法但正确 | 无规模意识，小数据硬上重型结构 |
| 复杂度分析伴随取舍（内存/预计算/近似） | 复杂度只报结论 | 思路自身逻辑不通 |
| 口述伪代码分层清晰、可讨论 | 叙述混乱但方向对 | — |

**示例题**：工单系统每天新增 50 万条，要支持"关键词 + 时间范围"的运营侧检索，容忍分钟级延迟。给检索方案思路（数据结构选型、写入/查询链路），口述或伪代码即可。
（锚点："容忍分钟级延迟" → 可异步建索引，不需要实时 ES——考"规模与约束决定方案"）

## ⑥ 题型配比速查（派生自 SoT「面试题型配比」行）

| 层级 | 时间占比 | 要点 |
|------|---------|------|
| 专家/正式岗 | 系统设计 ≈50-60% · 项目深挖 ≈30% · 算法思路 ≤10%（或不考）· 元能力贯穿 | 系统设计为主战场；手写代码不作为资深岗题型 |
| 外包/初级岗 | 项目深挖 + 元能力为主 · 系统设计降为场景理解 · 算法不考 | 探底 + 可引导性优先 |
| 实习生岗（校招） | 编程基础（可手写代码）· 潜力 · 诚信一票否决 | 保持原制，不套用资深岗配比 |
