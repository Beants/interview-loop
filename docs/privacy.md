# 私有数据与隐私边界

本文件固化 `interview-loop` skill 与本仓库的隐私契约，防止未来回归。

## 一句话边界

> **`skill/` + `examples/` 公开；`data/` 私有；真实面试数据绝不入库；skill 对数据位置无感。**

## 三重防护

防止真实面试数据（候选人姓名 / 公司 / 录音 / 录音转写）误提交到公开仓库，靠三层叠加：

| 层 | 机制 | 作用 |
|---|---|---|
| 1. 目录约定 | 真实数据**只允许**放进仓库根的 `data/` | 给私有数据一个单一、显式的归宿 |
| 2. `.gitignore` | `data/*` 全忽略，白名单仅留 `.gitkeep` / `README.md`；同时忽略 `.DS_Store` / `__MACOSX/` / `*.zip` | 即便误放进 `data/` 也不会被跟踪 |
| 3. PII 扫描 | `scripts/check-pii.sh`（CI 硬门禁）扫描真实姓名 / 公司 / 私有路径 | 即便 `.gitignore` 漏了仍能兜底拦截 |

> ⚠️ 我们**故意不**使用 `*简历*.md` 这类宽泛通配符来做防护——它会误伤 `examples/` 下的合法虚构示例。防护只靠「目录约定 + gitignore + 扫描」三重，不靠危险通配符。

## skill 对数据路径的处理（关键契约）

1. **skill 内部只允许相对路径**。任何 `/Users/...`、`C:\...` 绝对路径的 PR 一律拒绝。
2. skill **不引用** `examples/`，也**不引用** `data/`——它对数据位置无感：
   - 输入由调用方（agent 或人）在运行时提供；
   - 输出写到当前工作目录下的 `面试分析/`。
3. `examples/` 与 `data/` 是**仓库层**的设施（演示 + 私有落点），不是 skill 的依赖。

### 作者本地如何用真实数据运行

- 方式 A：把真实面试数据**复制**（不要软链，避免泄漏绝对路径）进 `data/`，在 `data/` 目录下运行 skill。
- 方式 B：直接在原私有仓库目录下运行 skill——skill 不关心 cwd 在哪。

## 库外运行的隐私盲区与脱敏自检（重要）

`scripts/check-pii.sh` **只扫描仓库根 `REPO_ROOT`**（工作树 + git 历史）。但 skill 把输出写到「当前工作目录下的 `面试分析/`」（见上「方式 B」）。**一旦 cwd 在本仓库之外，真实评价产物永远不会被 PII 门禁扫描**——这正是真实使用的主路径，三重防护的第三层对库外产物失效，必须靠下面的契约补上。

**输出落点契约（任选其一）：**

1. **落回 `data/`**：把库外产出的 `面试分析/` 复制（不要软链）进仓库 `data/`，`bash scripts/check-pii.sh` 会扫描它；提交前再跑一次。
2. **就地脱敏自检**：`scripts/check-pii.sh` 支持对任意目录做一次性扫描——
   ```bash
   bash scripts/check-pii.sh /path/to/你的/面试分析
   ```
   它用同一套 generic + project 模式扫描该目录工作树（不含 git 历史；project 模式仍从仓库 `scripts/pii-patterns.local` 或 `$PII_PATTERNS` 加载），命中即 exit 1。**对外交付 / 提交前务必先跑一次，0 命中再发出。**
3. **绝不**把库外真实产物直接 commit / push（`data/` 有 gitignore 兜底，库外路径没有）。

## 对外交付脱敏规范（发到 issue / PR / 邮件 / 文档前必做）

把分析结果发到仓库外（Multica issue、PR 描述、对外文档）时，**先脱敏**：

- **化名**：真实候选人一律改「候选人 A / B / C…」，真实面试官 / HR 同理；绝不贴真实姓名。
- **去直接标识符**：删除手机号、邮箱、身份证、详细住址；公司名按需模糊（「某头部内容平台」）。
- **不贴绝对路径**：不写任何绝对路径（macOS home 路径、Windows 盘符路径等）；引用代码用相对路径 + 行号（`path/to/file.md:42`），不贴 `file://` 链接。
- **量化指标按需**：真实业务数字若可反推身份，用区间或脱敏（「QPS 数万级」）。
- **自检**：脱敏后用上面的 `check-pii.sh <目录>` 跑一次，0 命中再发出；不确定就当有 PII 处理。

## 脱敏说明

仓库中所有示例人物、公司、项目、产品、指标均为**虚构同构数据**，仅保留结构与方法论，
不指向任何真实个人或组织。`examples/README.md` 对此有显式声明。

## 如何新增 PII 模式

如果你的真实数据里有新的、需要被扫描拦截的指纹（姓名 / 公司 / 项目名），把它加进
`scripts/check-pii.sh` 的 `NAMES` / `COMPANY` / `FINGERPRINTS` 列表，并在本地跑一次：

```bash
bash scripts/check-pii.sh
```

CI 会在每个 PR 上自动跑同一份脚本，命中则阻断合并。
