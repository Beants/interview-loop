候选人：林沐（虚构）
应聘岗位：后端架构师 / AI 工程化专家
应聘公司：星澜科技（虚构）· 智能平台组
面试官：陈思齐（虚构，技术）
面试日期：2026-06-10（示例）
面试时长：约 48 分钟
面试形式：视频面试
------------------------------------------------------------
⚠️ 本记录为完全虚构内容，与任何真实人物 / 公司 / 项目无关。
============================================================

[00:00] 面试官：林沐你好，我是智能平台组的陈思齐。先请你简单介绍一下自己和 AI 工程化相关的工作经验。

[00:30] 林沐：好的。我工作 5 年，前两年多在做高并发交易系统的微服务化，最近两年多转到了 AI 工程化方向，主导了公司内部的知识库 RAG 系统和一个智能客服 Agent。最近一年主要在 LangGraph 上做多 Agent 编排。

[01:20] 面试官：那我们先从 RAG 这个项目聊起。你说召回准确率从 72% 提升到 88%，这个 72% 的 baseline 是怎么测出来的？

[01:35] 林沐：72% 是我们上线前用一批标注好的 query-doc 对做的离线评估，当时是纯向量召回。后来加了 BM25 做混合检索，又加了 reranker，最后到了 88%。

[02:10] 面试官：混合检索里向量召回和 BM25 的权重你是怎么定的？

[02:15] 林沐：一开始是拍的一个 0.7 / 0.3，后来我们在验证集上扫了几组，发现 0.6 / 0.4 在我们这个场景下 recall 更高一点，最后就定在这个。

[02:40] 面试官：reranker 用的是什么？为什么选它？

[02:45] 林沐：用的是 bge-reranker。选它主要是因为和我们用的 embedding bge-m3 是同一套体系，部署起来方便，而且当时公开榜单上表现还不错。

[03:10] 面试官：embedding 模型和 reranker 模型的区别你能说一下吗？输入输出分别是什么？

[03:20] 林沐：embedding 是把一段文本映射成一个向量，输入是文本，输出是定长向量，主要用来做召回；reranker 是输入一个 query 和一个 doc，输出一个相关性分数，主要用来精排。

[03:50] 面试官：你刚才说文档分块用的是按段落加语义的递归分块，具体怎么递归的？多大一块？

[04:00] 林沐：我们设了一个上限，大概 512 token，先按段落切，如果一个段落超过上限就再按句子切，切完之后相邻的小块会尽量合并到接近上限，保证不会太碎。

[04:30] 面试官：你们怎么处理 RAG 的幻觉问题？

[04:35] 林沐：主要几层。第一层是 Prompt 里明确要求"只能基于检索到的内容回答，不知道就说不知道"；第二层是要求模型在回答里带上引用的段落编号；第三层是我们做了一个简单的后校验，把回答里的引用和检索结果做一次匹配，对不上的会标记出来给人工复核。

[05:20] 面试官：这个后校验是你自己写的还是用了什么框架？

[05:25] 林沐：自己写的，规则比较简单，就是看回答里声称的引用编号是不是真的出现在召回结果里。

[05:40] 面试官：好。换个话题，你简历里写到客服 Agent 的工单自动解决率从 35% 到 60%，这个 35% 是怎么来的？

[05:55] 林沐：35% 是我们上 Agent 之前，老的关键词路由 + FAQ 命中能自动解决的占比，这是运营那边统计的历史数据。

[06:15] 面试官：Agent 这边用的是 ReAct，死循环你们怎么处理？

[06:20] 林沐：我们设了一个最大步数限制，到了就降级到人工。中间也试过让模型自己判断是否该退出，但效果不稳定，后来还是用硬限制兜底。

[06:50] 面试官：你说上下文管理用对话裁剪加摘要压缩，长会话成本下降 40%，这个 40% 是 token 量的下降还是费用的下降？

[07:00] 林沐：是 token 量的下降。我们把超过一定轮数的早期对话先做摘要，只保留摘要 + 最近几轮原文，token 量大概降了 40%。费用是按 token 算的，所以基本同比例。

[07:30] 面试官：LoRA 你用过吗？Rank 和 Alpha 一般怎么选？

[07:35] 林沐：LoRA 我自己没真正训过，只是了解概念。Rank 我知道一般选 8 到 64，Alpha 一般是 Rank 的 2 倍左右，但具体为什么这么选我说不太清楚，这块我确实没实操经验。

[08:00] 面试官：没关系。那你用大模型一般怎么选？什么情况下你会考虑微调，什么情况下用 Prompt 就够了？

[08:10] 林沐：我一般先用大模型加 Prompt 验证可行性，如果效果不够，而且任务是比较固定的模式，比如意图分类这种边界比较清晰的，我会考虑收集数据微调一个小模型降本。但如果任务很开放，我还是倾向用大模型加好的 Prompt 和工具链。

[08:50] 面试官：好。最后给你一个开放题：如果要你给我们的知识库系统做一个评估体系，你会看哪些指标？

[09:00] 林沐：我会分几层。检索层看 recall 和 precision，这个用标注集能算；生成层看回答的正确性、是否有幻觉、是否带引用，这个我们用 RAGAS 跑；业务层看用户满意度和人工复核介入率。我觉得最重要的是检索层的 recall，因为召回不来后面都白搭。

[09:50] 面试官：挺好的。你有什么想问我的？

[10:00] 林沐：我想问一下，团队目前在模型层是主要用 API 还是有自研微调的计划？还有就是这个岗位未来半年主要会负责哪块？

[10:30] 面试官：目前以 API 为主，自研在规划里但优先级没那么高。岗位的话，前半年主要接手知识库系统的二期和客服 Agent 的重构。……（后续为候选人提问环节，从略）
